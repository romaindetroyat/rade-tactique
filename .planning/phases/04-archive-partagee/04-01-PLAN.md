## Décisions de planification (recherche 04-RESEARCH.md)

- Un seul document léger par environnement (`<env>/light.json`), fusionné par le serveur : lire (`useCache:false`) → fusionner → écrire avec `ifMatch` (Open Questions 1, 5 ; Patterns 1, 2, 4). Pas de journal d'opérations : l'état marqué est la file d'attente (Open Question 2).
- `stampState` et `markDirty` vont dans `js/archmerge.js` (le prototype les plaçait dans `js/archsync.js`) : `saveReg` en a besoin à tout instant, alors que `js/archsync.js` ne sera chargé qu'après la carte (Pitfall 16). `slug` y va aussi (le serveur l'utilise pour les objets de jour du plan 04, la page devra calculer le même).
- Ce plan ne livre que `k=light` ; tout autre `k` répond 400 « k inconnu ». Les routes `day`, `trace` et `report` arrivent au plan 04 (découpage D-02 : la v30 n'en a pas besoin).
- En-tête `x-rt-membre` = `encodeURIComponent(prénom)` : une valeur d'en-tête doit rester en octets simples ; la fonction la décode (sous `try`) puis la valide (`/^[\p{L}\p{M} '’-]{1,40}$/u`) ; refus 403 `membre_inconnu` sinon (fermée par défaut).
- Les réponses JSON de `k=light` portent `env` (`prod` ou `preview`) : l'indicateur du plan 02 ajoutera « (essai) » sur l'aperçu.
- Dépendance : `@vercel/blob` **2.8.0 exactement**, approuvée par l'orchestrateur (paquet officiel Vercel), sans point de contrôle humain. Vérifié par le planificateur le 20/10/2026 (`npm view`, `npm pack`) : 2.8.0 publiée le 10/08/2026, dépôt `github.com/vercel/storage`, aucun script `preinstall`/`install`/`postinstall`, intégrité `sha512-Nu+HWKpkgovCh/ezlG7wCVwF7RErTzLzZMbGKFBdGBCbTKyK+s5VXPLl+0+TpNEQPH8AVaGzOpIsXUOtkqylCQ==`, exports `get`, `put`, `head`, `BlobError`, `BlobPreconditionFailedError`, `BlobNotFoundError`, `BlobServiceRateLimited` ; `get` rend `null` si l'objet est absent et `statusCode: 304` (flux nul) quand `ifNoneMatch` correspond.
